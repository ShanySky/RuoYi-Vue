# 执行上下文与能力边界

> 类型：项目级 Rule
>
> Canonical source：`ShanySky/RuoYi-Vue/.agents/rules/execution-context.md`
>
> 前端仓库 `ShanySky/RuoYi-Vue3` 保留同路径 mirror，保证只打开前端仓库时也能独立工作。项目级语义发生变化时，以本文件为准并同步 mirror。

本规则用于让同一套仓库级 Agent 约定同时适用于本地 Codex、ChatGPT / GitHub 云端协作、CI Runner 和用户明确指定的远程执行环境。

核心原则：

> **先识别当前执行上下文和真实可用能力，再选择执行方式。工具存在不等于已经授权切换环境；验证深度也不等于执行环境。**

## 1. 先锚定当前执行上下文

开始实施、验证或 Git 操作前，先判断当前任务实际从哪里开始：

- 本地 Codex / 本地代码工作区。
- ChatGPT / GitHub 云端协作环境。
- GitHub Actions 或其他 CI Runner。
- 用户明确指定的 SSH / 远程服务器 / 临时运行环境。
- 其他由当前任务明确建立的环境。

当前任务已经通过哪一种环境开始访问和操作仓库，就默认在该执行上下文中持续推进。

不要仅因为工具列表中还能看到其他 Connector、本地工作区、SSH、远程服务器或云端执行工具，就自行把任务切换过去。

用户在当前任务中对执行环境的明确指令优先于默认判断。

## 2. 再确认当前能力

不要根据产品名称猜能力。只依据当前环境真实可用的能力决定下一步，例如：

- 是否能读取 / 修改当前 Working Tree。
- 是否能运行 shell、Maven、Node、Docker、浏览器或数据库命令。
- 是否能执行本地 Git。
- 是否能访问或写入 Git 远端。
- 是否能调用 GitHub API、创建 PR、运行 Actions。
- 是否能访问配套前端 / 后端仓库。
- 是否具备 MySQL、Redis、网络、浏览器或公网预览能力。

某项能力不可用时，不要假装已经执行，也不要因为“理论上可能存在另一个工具”就自行跨环境。

## 3. 默认留在当前上下文

如果当前执行上下文已经能够完成任务，应优先在当前环境内完成实施和验证。

只有以下情况才切换到其他执行环境：

1. 用户在当前任务中明确要求使用另一个环境；或
2. 当前环境确实无法完成关键步骤，且跨环境是必要方案，并已获得用户许可。

例如：

- 本地 Codex 可以正常编译、启动和测试时，直接使用本地环境，不必为了“真实验证”改跑 GitHub Actions。
- ChatGPT 正通过 GitHub 仓库和 Actions 推进时，不得仅因为存在用户电脑连接器就进入用户本机。
- CI Runner 中的任务不要因为本地命令更方便就假设存在用户本地文件。

## 4. 能力缺失采用局部降级，不把整个任务误判为无法推进

能力缺失只阻塞真正依赖该能力的步骤。

例如：

- 可以修改、测试和本地提交，但不能 Push / 建 PR：先完成前者，只把远端收口步骤标记为未完成。
- 当前只打开后端仓库、无法读取前端：继续完成不依赖前端事实的工作；只有真正依赖前端契约的判断才标记受阻。
- 当前能做静态检查但无法启动数据库：不得宣称数据库验证通过，但可以先完成静态与单元级验证。

不要因为一个非关键能力缺失就停止所有可继续工作，也不要为了绕过能力缺失擅自寻找新的执行环境。

## 5. 验证深度不决定执行环境

“真实运行验证”“自动化验证”“启动服务”“执行 E2E”“连接数据库”等描述的是需要证明到什么程度，不隐含必须使用某一种物理环境。

验证应遵循：

1. 先确定需要证明的行为。
2. 在当前执行上下文中使用真实可用能力完成能够完成的最强证据。
3. 如果关键证明在当前环境无法完成，明确指出具体缺口。
4. 只有确有必要且得到授权时，才切换执行环境补齐证明。

## 6. 区分共享远端事实与当前实施事实

- `master`、`chatgpt/ai-agent-assistant` 等共享分支的最新共同状态，以 canonical Git 远端为准；需要判断共同主线是否变化时应核实远端。
- 当前正在实施的未提交修改、本地提交、临时配置和真实运行结果，以当前 Working Tree / 当前执行上下文为准。
- 不要用远端旧状态覆盖当前未推送实施事实，也不要把本地未推送状态描述成已经进入共享主线。

## 7. 环境特定方案必须标明适用条件

Rule / Skill 中出现以下内容时，应明确它属于哪种环境或能力条件：

- GitHub Connector / GitHub API。
- GitHub Actions / `GITHUB_TOKEN`。
- 本地 Git 命令。
- Linux 专属路径、`sudo`、`--network host`。
- Windows / PowerShell 专属命令。
- SSH / 远程服务器。
- Cloudflare Tunnel 或其他公网预览方案。

环境特定 workaround 可以保留，但不能写成所有执行环境都必须照做的唯一流程。

## 8. 完成与汇报

最终汇报应区分：

- 当前执行上下文。
- 实际使用了哪些能力。
- 哪些实施 / 验证已经真实完成。
- 哪些步骤因为当前能力不足尚未完成。
- 是否发生过执行环境切换，以及该切换是否来自用户明确要求或授权。

不得把“当前环境无法执行某一步”改写成“整个任务已完成”，也不得把“存在可用工具”改写成“已经获得跨环境操作授权”。
