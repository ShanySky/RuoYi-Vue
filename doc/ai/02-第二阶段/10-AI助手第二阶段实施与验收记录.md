## 2. 第二阶段完成内容

### 2.1 Runtime 与 Bug 修复

- Provider 返回的 `tool_call.id` 不再直接作为数据库/浏览器内部调用 ID。
- Runtime 为每次页面 Tool Call 生成自己的唯一 `rtc_*` ID，重复、为空或不规范的 Provider callId 不再导致数据库唯一键冲突。
- pending 状态持久化失败不再向前端直接暴露 SQL/约束异常。
- Backend CI 故意让测试 Provider 在同一个 Conversation 的第二轮重复返回同一个 tool_call.id，两轮均成功完成并进入 RESOLVED。
- 用户管理语义明确：
  - `userName` = 登录账号，现有 RuoYi 编辑流程不支持修改。
  - `nickName` = 用户昵称，可通过当前 AI 页面 Tool 修改。
- System Prompt、后端 Tool Policy、前端 Tool 描述和预览 mock 均同步该语义，不再把登录账号修改误映射成昵称修改。

### 2.2 AI 窗口

AI 助手现在支持：

1. 收起：右下角 AI 按钮。
2. 默认：右下角非模态小聊天窗口。
3. 展开：右侧 Dock 工作区。

行为：

- 小窗和 Dock 都不产生聊天遮罩。
- AI 打开时业务页面仍可正常查看和操作。
- Dock 占据右侧真实布局宽度，主业务页面和 fixed header 被压缩，而不是被覆盖。
- Dock 默认宽度约 560px，可拖动调整，并持久化宽度。
- 小窗 / Dock / 收起切换共用一套 Conversation、消息、Tool 状态、模型、reasoning 和输入状态。

### 2.3 输入快捷键

默认：

- Enter：发送。
- Shift+Enter：换行。

可切换为：

- Ctrl+Enter：发送。
- Enter：换行。
- Shift+Enter：换行。

发送方式保存到浏览器 localStorage，并已通过页面重载后的自动验收。

### 2.4 聊天内快捷设置与 Provider 语义

小窗和 Dock 均提供快捷“设置”入口，不需要离开当前业务页面。

Provider 操作现在明确分开：

- “保存连接配置”只保存 Base URL、Token、启用状态等 Provider 信息，不隐式新增模型。
- “测试模型加载”使用当前表单临时调用 `/models`，验证地址、Token 与远端模型目录加载能力，不写模型数据库。
- “选择模型”从已加载远端目录中搜索、多选，确认后才将选中的模型加入系统。
- 请求超时仍由后端保留为技术参数，普通 UI 不展示，当前默认 30 秒。
- 完整 AI 配置页与快捷设置使用同一套后端数据和同一模型生命周期。

### 2.5 远端模型目录、系统模型与联想搜索

模型状态现在明确分为：

1. Provider `/models` 返回的远端发现模型。
2. 用户明确选择并加入系统的模型。
3. 已启用模型。
4. 唯一默认模型。

行为：

- 测试/刷新远端目录不会自动把几十或几百个模型写入 `ai_model`。
- 远端模型选择器支持约 180ms debounce、前缀优先与包含匹配、多选和“已在系统中”标记。
- 只有点击“添加所选模型”后，选中的模型才进入系统模型目录。
- 系统模型支持启用、移除、默认五角星、默认 reasoning effort 和单模型测试连接。
- 移除模型采用软移除，历史消息和 pending Tool Call 的模型引用继续保留。
- 聊天模型选择器只展示已经加入系统且已启用的模型。
- 最近使用模型仍保存于浏览器本地。

### 2.6 默认模型、自动能力检测与 Reasoning Effort

- 第一个加入系统且启用的模型在没有既有默认模型时自动成为默认模型。
- 默认模型以亮色五角星呈现；切换默认模型只需点击星标。
- 禁用或移除当前默认模型时，系统会在剩余已启用模型中自动选择新的默认模型。
- 新模型加入系统后自动检测 Tool Calling 与 reasoning capability，不再要求用户先手工点“思考测试”。
- reasoning 检测会先确认模型基础调用正常，再尝试标准档位：
  - minimal
  - low
  - medium
  - high
  - xhigh
- Provider 接受的档位记录到 `reasoning_efforts`；支持 reasoning 时直接显示默认档位下拉框。
- 明确不支持时显示“不支持”；调用异常或无法判断时保持 UNKNOWN 并提供“重新检测”。
- 聊天输入区只常驻显示模型，reasoning 仍通过模型选择器二级入口按下一轮切换。

### 2.7 同一会话切换模型 / 档位

同一 Conversation 可以在后续用户消息中切换：

- modelId / modelCode。
- reasoningEffort。

新选择从下一条新的用户消息开始生效。

如果上一轮正在等待页面 Tool Result：

- Tool Result 恢复时强制使用产生该 pending Tool Call 时保存的原模型和原档位。
- UI 此刻的新选择不会污染旧 pending call。
- Fullstack E2E 已专门验证：Tool Call 由主模型/High 产生，Tool Result 请求故意携带第二模型/Low，Runtime 仍以主模型/High 恢复。
- 下一条新的用户消息才使用新的选择。

数据库现在可以追溯每条消息/Tool Call 实际使用的：

- modelId。
- modelCode。
- reasoningEffort。

### 2.8 数据库升级

最新版 `sql/ai_20260918.sql` 已包含 reasoning、每轮模型追溯和系统模型 selected 状态。

已有环境按版本顺序使用：

- `sql/ai_phase2_20260918.sql`：补充 reasoning 和每轮模型追溯字段，并处理旧 PENDING Tool Call。
- `sql/ai_model_selection_20260918.sql`：增加显式模型选择状态；此前由旧版“同步全部模型”自动导入但从未实际启用/配置的模型会从系统模型列表隐藏。
- 已启用、已设默认、已完成能力检测或设置过默认 reasoning 的旧模型会保留，避免影响实际使用数据。

## 3. 正式 Provider 与 Mock 边界

正式产品仍以用户配置为唯一运行来源：

`Base URL + Token → 保存连接 → 测试模型加载/获取远端目录 → 用户选择模型 → 加入系统并自动检测能力 → 启用/默认 → Agent 调用该 Provider`

最终源代码审计确认：

- 产品源代码中没有写死 `mock-agent-model`。
- 产品源代码中没有写死预览 mock 地址。
- 产品源代码中没有 CI/Preview Token。
- 不存在正式 Provider 失败后自动回退到 mock 的逻辑。

mock 只存在于：

- Backend CI。
- Fullstack E2E。
- 临时 Public Preview workflow。

本次没有用户提供可用于外部第三方模型服务的真实 Token，因此没有对某个具体第三方 Provider 做专属凭据验证；OpenAI-compatible 请求链、远端模型目录加载、显式模型选择、自动能力检测、reasoning 参数、Tool Calling 和动态 Base URL/Token 路径均已通过隔离测试 Provider 完整验证。

## 4. 日志与安全基线

第一阶段日志保护继续保持：

- sys-info：50MB/文件，30 天，1GB 总上限。
- sys-error：20MB/文件，30 天，512MB 总上限。
- sys-user：50MB/文件，30 天，1GB 总上限。
- 历史日志 gzip。
- AI 默认 INFO。
- Spring AI 默认 WARN。
- Provider Token AES/GCM 密文存储。
- Provider 保存操作日志排除 Token。
- Prompt / Response / Token 不默认全量写入普通日志。
