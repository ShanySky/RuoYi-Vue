## 3. 三个阶段的定位

### 第一阶段：建立最小真实闭环

完成：

- Provider / Model。
- 普通聊天。
- Agent Loop。
- 当前页面 Frontend Tool。
- WRITE 确认。
- 用户管理真实业务修改。
- MySQL / Redis / Spring Boot / Vue / CI / E2E 全栈验证。

详见：`../01-第一阶段/`

### 第二阶段：从 Demo 变成可长期使用的助手 UI

完成：

- 非模态小窗 + Dock。
- 快捷设置。
- 多模型管理与实时搜索。
- 默认模型和 Reasoning。
- 同一 Conversation 后续轮次模型切换。
- 第一阶段稳定性修复。

详见：`../02-第二阶段/`

### 第三阶段：把助手提升为应用级 Agent

完成主要能力：

- Run / Stop / Steering。
- Prompt Cache。
- Context Budget / Checkpoint / Compaction。
- 统一 Page Capability。
- 多页面接入和跨页连续操作。
- 应用级 Conversation / Run / UI 恢复。
- 用户会话历史与偏好。
- AI 管理分层。
- 管理员只读审计。

第三阶段自动实现、自动验收和当前 HEAD Real GPT 验收已经收口；原验收记录保留 R3-09 主观视觉人工确认作为最后用户侧确认项。

详见：`../03-第三阶段/`

## 4. 当前最重要的下一步

当前不建议直接继续堆大量第四阶段功能。

优先进入一次架构加固讨论，核心候选项：

1. AgentRuntime SPI。
2. Agent Loop 职责拆分。
3. Run State Machine。
4. Page Capability Adapter 解耦。
5. Tool Policy Registry 拆分。
6. AiAssistant / QuickSettings 职责拆分。
7. Prompt Version History。
8. Capability / Agent 协议版本化。
9. Agent 核心 Unit / Integration Test。
10. AI SQL Migration 规范。

完整复盘见：

`../04-架构复盘与演进/14-AI助手三阶段架构复盘与后续优化建议.md`

这些项目目前是架构复盘建议，不代表已经全部批准进入实施。后续讨论确认后，再形成独立 Phase 3.5 实施计划。

## 5. 更新规则

发生以下情况时应更新本文件：

- 某项全局能力完成或状态发生明显变化。
- 某个“规划方向”被正式批准进入实施。
- 某个长期方向被明确取消。
- 总体设计发生架构级调整。

日常小修复和每次 commit 不需要在这里记录。
