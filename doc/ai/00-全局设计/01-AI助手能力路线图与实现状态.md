> 原则：本文件用于快速回答“现在已经有什么、哪些还需要完善、下一步重点是什么”。已实现状态以当前 `chatgpt/ai-agent-assistant` 代码及对应验收记录为准；新增阶段诉求不等于已经实现。

## 1. 状态说明

- ✅ 已实现并已进入当前开发主线。
- 🟡 已实现主要能力，但覆盖或架构边界仍需继续加固。
- ⬜ 尚未实现，已进入明确后续方向。
- 🔬 仅作为以后可能研究方向，不是当前承诺任务。

## 3. 三个阶段的定位

### 第一阶段：建立最小真实闭环

完成：

- Provider / Model。
- 普通聊天。
- Agent Loop。
- 当前页面 Frontend Tool。
- WRITE 确认。
- 用户管理真实业务修改。
- MySQL / Redis / Spring Boot / Vue / CI / E2E 全栈验证。

详见：`../01-第一阶段/`

### 第二阶段：从 Demo 变成可长期使用的助手 UI

完成：

- 非模态小窗 + Dock。
- 快捷设置。
- 多模型管理与实时搜索。
- 默认模型和 Reasoning。
- 同一 Conversation 后续轮次模型切换。
- 第一阶段稳定性修复。

详见：`../02-第二阶段/`

### 第三阶段：把助手提升为应用级 Agent

完成主要能力：

- Run / Stop / Steering。
- Prompt Cache。
- Context Budget / Checkpoint / Compaction。
- 统一 Page Capability。
- 多页面接入和跨页连续操作。
- 应用级 Conversation / Run / UI 恢复。
- 用户会话历史与偏好。
- AI 管理分层。
- 管理员只读审计。

第三阶段自动实现、自动验收和当时验收版本的 Real GPT 验收已经收口；原验收记录保留 R3-09 主观视觉人工确认作为最后用户侧确认项，不将其伪造为已经确认。

详见：`../03-第三阶段/`

### 4.2 本轮推进方向

用户已明确要求按以下顺序自主推进：后端接口能力 → 受控数据库能力 → 较成熟的服务端执行框架。

诉求、决策来源、授权及阶段约束统一见 [29 号文档](../06-服务端能力演进/29-AI助手服务端能力演进诉求与推进约束.md)。先校准基线并研究渐进式披露，再逐阶段完成设计、方案、计划、实施和验收。三个新阶段目前均未实现。

历史文档中“Server Tools / Harness 延后”的结论描述的是 3.5 阶段范围，不能继续作为阻止本轮推进的依据。B7 估算精度、B8 执行管理只解决新阶段实际需要，不提前建设分布式平台或复杂自建执行框架。旧架构讨论分支不再作为当前工作入口。

## 5. 更新规则

发生以下情况时应更新本文件：

- 某项全局能力完成或状态发生明显变化。
- 某个“规划方向”被正式批准进入实施。
- 某个长期方向被明确取消。
- 总体设计发生架构级调整。

日常小修复和每次 commit 不需要在这里记录。
