# 执行框架部署与复验说明

> 2026-09-21；第三阶段和组合验收通过。设计 37、计划 38、实际版本与证据 39。本文件位于权威文档工作区；下面的产品路径指配对后端实施仓库。

## 交付组成

Java 17 后端包与 `runtime/pi/`、`runtime/workspace/` 一起部署。Pi 0.85.1 及依赖由 `package-lock.json` 锁定，许可见 `runtime/pi/PI-LICENSE`；Node 需 ≥22.19，本轮验证 22.22.2。前端仍使用 Node 20。框架是后端管理的可信子进程，模型命令仅交给 Linux 隔离服务，不能将工作空间服务管理接口公开给终端用户。

隔离服务要求 Linux、Docker、控制组第二版、默认系统调用过滤及可用的内存/交换/处理器/进程限制。启动时核查这些条件并将配置镜像解析成不可变标识，缺少保护即关闭能力。Python 3 标准库承担可信管理服务；文档生成库只安装在固定沙盒镜像内，全部依赖版本在 `requirements.lock` 中。容器不连接网络，不挂载宿主目录或管理套接字。

## 安装与启动

以下以单后端实例和同机 Linux 服务为部署边界。先配置现有 MySQL/Redis 与原 AI 服务，再按正常顺序应用 `sql/ai_migrations/`；新装使用 `sql/ai_fresh_install.sql`。不要把旧环境按新装脚本覆盖。

```sh
# 在后端仓库；使用指定的 Node 22 和 npm，不改变前端 Node 20。
cd runtime/pi
npm ci --ignore-scripts --no-audit --no-fund
npm test
cd ../..
mvn -B -Pprod -DskipTests package

# 在 Linux 隔离宿主构建固定镜像，镜像不能由模型指定或更新。
docker build -t ruoyi-ai-workspace:20260921 runtime/workspace
```

部署目录示例为 `/opt/ruoyi`，隔离服务数据目录 `/var/lib/ruoyi-ai-workspace`。安装随包服务文件 `runtime/workspace/ruoyi-ai-workspace.service` 前，将目录和路径调整为实际落点；该文件默认仅监听回环。创建随机至少 32 字符的服务凭证，保存到仅服务账号可读的文件 `/etc/ruoyi/workspace.token`，后端读取同一个凭证文件或受保护的等值副本。凭证内容不能进入命令行、仓库、模型消息或沙盒镜像。

在启用服务前创建上述数据目录和凭据目录，权限设为 `0700`、凭据文件设为 `0600`；服务文件的 `ReadWritePaths` 指向的数据目录必须已经存在。可信服务由受控部署账号管理 Docker，实际模型命令始终以容器 UID 1000 执行。

后端进程配置：

| 配置 | 示例与职责 |
|---|---|
| `RUOYI_AI_HARNESS_NODE` | 指定 Node 22 的绝对可执行路径 |
| `RUOYI_AI_HARNESS_HOME` | `/opt/ruoyi/runtime/pi`，包含锁定依赖和 `worker.mjs` |
| `RUOYI_AI_WORKSPACE_URL` | `http://127.0.0.1:28097`；非回环仅接受受保护的 HTTPS |
| `RUOYI_AI_WORKSPACE_TOKEN_FILE` | 服务凭证文件路径，只读取必要授权 |
| `RUOYI_PROFILE` | 原若依私有运行目录；框架临时目录位于其 `ai-harness/` 子目录 |

先启动隔离服务，再启动后端。后台“工作空间”页应显示环境已就绪，初始治理开关关闭；核对资源后开放，并将 `ai:workspace:use` 授给实际使用角色。`ai:workspace:view/edit` 只控制治理，不能替代使用权限。数据库和接口仍各自配置开放范围；业务写入继续使用原接口确认。

Linux 服务进程限制为 512 MiB、1 处理器和 96 进程；任务容器与文件限额见治理页及 37。日志最多三个 2 MiB 文件；容器关闭日志驱动，命令输出有界。备份需在无活动任务时保留后端数据库与隔离服务成果清单及文件的一致副本，不能备份不存在的临时任务空间。

## 停止与恢复

用户停止会取消若依运行，终止 Pi 进程并回收整任务容器；后端异常退出还由输入管道关闭和短租约保护。进程重启把旧活动运行收束为失败或取消、待办取消、未形成完整回执的执行记为未知；已经确认的业务事实保留，不自动续跑旧写入。当前是单实例生命周期，不将这份实现宣称为分布式调度服务。

成果保留 24 小时，临时环境随任务结束回收。有效成果下载始终需要当前身份、工作空间使用权限和原业务来源授权；关闭治理或撤权会阻止旧成果继续读取。低于 2 GiB 磁盘保护水位时不能创建或写入新任务。回收失败继续占用配额并写入受限诊断日志，不能直接修改清单释放额度；应先排查文件系统、Docker 和服务状态。

## 必要客户端边界

当前 `runtime/pi/worker.mjs` 的输入输出是后端到同机可信子进程的私有协议，不能直接暴露为远程客户端接口，尤其不能向客户端转发启动包中的提供方凭据。协议围绕所选 Pi：`start` 接收获批上下文/工具，`tool` 请求若依处理，`resume` 仅释放对应回执，`cancel` 终止当前执行；用户身份始终由后端运行归属查询得到。

未来客户端可安装同款 Pi，复用任务、调用标识、确认、取消及成果归属模型。远程接入必须另行将现有登录认证转换成绑定用户/运行/有效期、可撤销的任务授权；客户端声明能力不能扩大权限，业务写入仍由若依裁决，回传结果要按调用标识原子认领。模型凭据使用客户端自己的配置或专门受控代理授权，不能沿用私有进程启动包。这是本轮保留的适配边界，不表示已实现客户端安装器或通用多框架平台。

## 复验入口

本机完整恢复先核查 39 的最新进程、包摘要与配对提交，不对其他虚拟机操作。任务虚拟机介质全部在 `E:/VMDisk/RuoYi-AI-Evolution/`。验收脚本分别承担：

- `runtime/pi/worker.test.mjs`：真实开发库循环、动态工具、等待、取消、缓存兼容和未获批工具拒绝。
- `scripts/local/ai_workspace_acceptance.py`：真实容器身份/网络/挂载/内核配额、写满、进程/内存、停止及失租回收。
- `scripts/local/ai_workspace_storage_acceptance.py`：真实任务/用户/全局成果配额、到期读取租约及低水位。
- `runtime/workspace/storage_failure_test.py`：受控注入写入和删除失败，观察真实残留仍占用完整配额，修复后可回收。
- `scripts/local/ai_workspace_fullstack_acceptance.py`：本人业务数据到表格、文档、PDF、哈希及下载验证，跨用户和撤权反例。
- `scripts/local/ai_harness_lifecycle_acceptance.py`：杀死等待确认的框架、强制终止后端、正常重启后核对未知写入与孤儿回收；只在本任务专用环境运行。
- `scripts/local/ai_workspace_cancellation_acceptance.py`：实际隔离命令执行中，通过若依停止或撤销使用权限，核对容器回收及零模型续跑。
- `scripts/local/ai_workspace_limits_finish.py`：真实处理器节流、第二临时目录写满及慢下载并发/超时。
- `scripts/local/ai_real_harness_acceptance.py`：38 号预算内的真实接口→数据→三类成果；生成后保留夹具供前端核验，使用 `--cleanup <证据文件>` 清理。
- 前端 `tests/ai-workspace-e2e.mjs`：治理开关；设置 `WORKSPACE_FIXTURE` 为真实验收 `evidence.json` 时，验证本人三份成果下载、哈希和刷新恢复。
- 原模块、迁移和完整浏览器脚本继续验证接口、数据与原页面链路。真实模型仅通过 38 号持久预算代理，前两阶段账本不得重置。
