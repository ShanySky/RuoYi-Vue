## 3. 真实模型累计预算

接口阶段统一账本，不按重启、批次或场景清零。调用前先运行确定性测试。模型为 `gpt-5.6-luna`，完整读取用户授权的 `OPENAI_CUSTOM_BASE_URL` / `OPENAI_CUSTOM_API_KEY`，不打印值、不写源码或明文配置。

| 项目 | 阶段初始上限 |
|---|---|
| 输入词元 | 300,000，含能力探测、压缩和失败预留 |
| 输出及推理词元 | 40,000；单请求最多 4,096 |
| 上游请求 | 48，失败、参数兼容回退和重试均计入 |
| 工具调用轮次 | 40；单业务任务最多 12 |
| 重试 | 全阶段最多 2 次，仅在可判定的连接或协议错误后，业务写入不重发 |
| 单次 / 累计时间 | 120 秒 / 30 分钟上游活动时间；另设 60 分钟墙钟验收窗口 |

预算由测试侧本地代理在发出请求前原子登记并持久保存；拿不到用量时按本次预留上限计费，不当作零。凭据只进入代理内存，应用使用本地代理专用非真实令牌。真实调用前取当前计数，超过任一项就停止真实调用、保留证据并修正问题。追加预算必须说明依据并保留原累计，不通过新账本规避。第三方价格尚无可靠依据，暂不虚构金额上限。

## 4. 任务环境与清理预算

Java 17 和 Node 20 只在本次子进程选择，不改变宿主默认值。构建和测试日志保存在配对工作树父目录 `.validation/`，原日志不覆盖；每次执行记录时间、分支、提交与差异。

本机已有 MySQL/Redis 监听，但不据此修改其配置或已有数据。全栈环境优先建立专用 Linux 验证机承载 MySQL 8、Redis 7.4 及后续容器验收；运行服务按需放在任务环境，端口仅绑定回环地址。

专用机命名 `RuoYi-AI-Evolution`，所有占用空间归属 `E:/VMDisk/RuoYi-AI-Evolution/`：`machine/` 系统盘、`snapshots/` 快照、`backups/` 备份、`exports/` 导出、`images/` 安装介质。初始 4 个处理器、6 GiB 内存、24 GiB 动态系统盘；目录物理占用上限 32 GiB、宿主 E 盘最低保留 40 GiB；安装介质上限 2 GiB，不创建无必要快照或备份。单轮连续运行最多 6 小时，停止工作时正常关机；日志与缓存按任务保留，不清理用户既有虚拟机。创建前及创建后核对磁盘与快照实际路径。该环境不构成产品的 VirtualBox 依赖。

计划自审：每项 API 验收都有实施动作、判别性用例和运行入口；数据库新装与升级、配对分支、模型失败计数、环境资源与回收均已有责任落点。P1 的真实全栈基线尚待执行，不能以单元测试替代。
