### 真实模型失败、修正与预算追加

前三次尝试均保留原账本和夹具清理结果。第一次模型在统计请求中带 `columns:[]`，原参数定义拒绝无关空数组；已允许空数组等同省略，实际查询编译仍拒绝非空的无关字段，并补测试和五种范围真实统计复验。第二次模型用结果读取 `limit:100` 超过 50，上限正确拦截但错误在准备阶段变成通用运行失败；现将只读参数校验错误记为失败工具结果，允许模型理解并修正参数，写入确认校验不变。真实 `limit:100` 拒绝后 `limit:1` 成功已验证。

第三次目录为空来自 Java 注解 `toString()` 的成员顺序跨进程不稳定，误触发契约变化关闭。8 次独立 Java 探针保存 `.validation/annotation-order-evidence.json`；改为按固定属性顺序计算范围契约，增加顺序测试。最终同一包在 PID 80104 与 118716 的真实重启核验通过：`.validation/data-restart-verified-20260921-061111.json`，库和三张表指纹、开放状态完全相同，没有削弱变更失效规则。空目录提示同时明确不能推断业务数据为零；收费任务增加调用前治理前提检查。

按 29 第 5 节，35 R2 自审决定仅追加一次完整任务机会，重试累计上限从 2 调整为 3，其余上限及原开始时间不变。一次性迁移脚本核对同包重启证据与现有 12 条成功结算记录，保留原账本副本和校验值，拒绝重复执行；迁移后 8 项预算测试通过。后端启动脚本增加可执行清单与就绪检查：曾因构建尚未重打包就启动而得到不可执行包，记录保留，最终包等待构建结束后启动成功。
