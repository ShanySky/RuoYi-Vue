# 后端接口能力诉求与方案

> 版本：2026-09-21 / R1；状态：方案自审通过，实施与验收尚未完成。
> 上位约束：[29 号文档](29-AI助手服务端能力演进诉求与推进约束.md)；执行计划：[31 号文档](31-后端接口能力实施计划.md)；证据与恢复点：[32 号工作笔记](32-后端接口能力实施与验收工作笔记.md)。

## 1. 本阶段必须得到什么

用户在任意页面发起业务任务，助手可以发现本人有权使用且管理员已开放的后端接口，按需理解参数，通过原业务入口完成查询或经本人确认的写入，读取必要结果。新增遵循标准契约的接口自动进入治理目录，业务开发者不用再写一份 AI 登记清单。

验收以真实业务效果为准：用有不同权限和部门数据范围的账号，完成岗位查询、岗位新增与修改、部门范围内用户查询等任务；证明未授权、发现后撤权、停止后执行、重复确认及跨用户结果读取均不能产生越权数据或额外业务副作用。原页面工具、普通业务、写入确认、停止、纠偏、历史、压缩、设置与只读审计继续成立。

本阶段不实现数据库直查、文件和任意命令执行，也不重建任务编排。数据库和执行框架分别在本阶段和下一阶段验收后进入完整实施。

## 2. 决策来源与取舍

沿用 D-002、D-003、D-004、D-006～D-009、D-014～D-020：业务接口是权威，AI 开放只收窄权限，状态与审计复用现有会话和运行。自动发现、逐接口治理、渐进披露、撤权及时生效与成本预算来自用户本轮要求。

以下是本轮自主选择，可被真实测试修正：

| 问题 | 选择与理由 | 否决或保留条件 |
|---|---|---|
| 契约来源 | 从 Spring 已注册的请求映射、权限注解、参数类型、校验注解及接口说明生成目录和参数模式 | 不维护手工业务接口清单；不理解的非标准契约显示不支持原因并禁止开放 |
| 执行路径 | 后端以当前登录令牌向本进程实际监听端口发起固定回环请求，再走过滤器、控制器代理、校验、业务服务、事务及操作日志 | 不直接反射调用方法；模型不能指定地址、请求头、任意路径或登录身份 |
| 权限新鲜度 | AI 请求和受控回环请求重新从数据库加载用户、有效角色、菜单权限与数据范围；每次业务执行和披露重新校验 | 不把 Redis 登录快照当作最新业务授权；账号禁用、删除、会话注销立即拒绝新操作 |
| 工具披露 | 常驻搜索、详情加载、结果读取三个小工具；详情加载后，下一次模型请求只增加已授权的具体业务工具，最多保留 8 项 | 不把全量接口模式塞入提示；不启用未显式提供工具的解析回退；不依赖提供方专属协议 |
| 写入 | 所有非只读动作至少按 WRITE 确认；确认绑定服务端持久化的调用、参数、用户和运行 | 浏览器不提交执行事实；同一调用原子认领一次；超时或进程中断后的未知结果不自动重试 |
| 结果 | 原始有界结果保存在有期限、绑定用户和来源授权的句柄后；模型按路径、页码读取有限内容 | 不跨用户共享；授权或数据范围变化后拒绝旧结果及其派生历史再次披露 |

## 3. 真实契约与治理

目录键由请求方法与规范路径稳定派生；模块、对象和动作由路径、权限码及现有说明派生。参数按路径、查询、请求体分组，类型与校验取自真实方法签名和领域对象。识别单一方法、明确路径、标准权限注解、可序列化参数及 JSON 返回的常规业务接口。文件流、上传、通配路由、无法理解的权限表达式或特殊请求条件先列出原因并关闭，不能降级猜测。

治理表只保存接口键、契约指纹、启停、变更人和时间。默认关闭。管理员通过“AI 管理 / 后端接口”按模块、对象查看目录并逐接口开放；查看和修改分别使用独立菜单权限。业务路径、权限、参数模式仍由代码派生。契约指纹改变时旧开放失效，要求管理员重新核查，防止同一路径悄悄扩大能力。

模型搜索目录须同时满足原业务权限和 AI 开放策略。治理管理员可查看目录元数据，但不因此获得执行权限；原业务权限不明的接口不能开放。新接口测试通过运行时注册一个真实标准控制器证明发现与默认关闭，无额外 AI 登记。

## 4. 身份、执行与运行事实

### 4.1 授权与披露

刷新身份沿用 `SysPermissionService` 的角色与权限装配规则，让原 `@PreAuthorize` 和数据范围切面读取当前身份。权限检查不得只在模型工具列表生成时发生；搜索、详情、实际执行、结果读取及模型续跑分别检查。

受控回环请求带短期一次性内部凭证，绑定当前用户、精确方法、路径与持久化调用。凭证只在服务端内存和回环请求存在，不返回模型或浏览器。实际控制器开始前再次核对运行和调用状态。地址固定为实际监听的回环地址，不使用用户输入、代理头或模型参数拼接远程主机；禁止重定向和自动重试。

授权摘要包含账号状态、部门、有效角色、菜单权限、角色数据范围、自定义部门授权及部门层级事实。结果保存和返回前再次比较，检测执行期间撤权。摘要变化采用保守失效：旧结果不再读取，旧业务会话不再把敏感历史、模型答案或检查点送给模型或用户。已经交付给浏览器的内容无法撤回，边界是下一次服务端披露。审计仍保留运行元数据，审计权限不单独授予业务结果内容读取权。

### 4.2 调用状态与确认

复用 `AiPendingToolCall`、会话单活动运行和消息配对。具体业务工具持久化后再执行；只读工具由服务端执行，写入工具返回原确认卡片。前端确认只提交调用编号和同意/取消，实际参数从服务端读取，浏览器伪造结果不能推进运行。

服务端调用记录区分待确认、执行中、成功、失败、取消和结果未知。原子状态更新保证重复请求不能重复执行。同一运行中相同写入参数另行发起也要被去重。确认后撤权或停止时不进入业务控制器。执行中停止阻止后续动作；已经发生的业务写入保留真实记录。请求已发出却无法证明结果时标记未知，禁止自动再次发送；后续须经查询核对事实。

阶段一只增加必要的服务端工具分支，不引入第二套运行或通用编排器。阶段三替换模型工具循环时继续使用这些授权、业务入口和调用事实。

## 5. 渐进披露、结果与上下文

2026-09-21 补充核验官方资料：

- [Spring AI 动态工具检索](https://docs.spring.io/spring-ai/reference/api/tools/tool-search-tool.html)：先发送少量搜索工具，再追加命中的具体工具定义。
- [Spring AI 工具解析](https://docs.spring.io/spring-ai/reference/api/tools.html)：未显式提供工具的解析回退可能扩大可执行集合，本阶段保持关闭。
- [MCP 工具](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)与[资源](https://modelcontextprotocol.io/specification/2025-06-18/server/resources)：借鉴目录分页和内容按需读取，不引入额外协议平台。
- [Spring 请求拦截](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-servlet/handlermapping-interceptor.html)：安全检查优先放在过滤器链，不能仅依赖路径匹配的业务拦截器。

现有运行使用原始模型调用和应用生命周期。直接使用接管工具循环的官方检索顾问会绕开当前确认与运行控制，因此复用其披露机制，在现有边界内实现小型检索与已加载工具集合；不为了接入顾问重构整个循环。普通函数调用兼容性通过真实请求确认。

初始上限：搜索一页 20 条，单运行加载 8 个接口，业务分页一页最多 50 行，原始结果最多 256 KiB，单次模型读取最多 8 KiB，结果保留 30 分钟；每用户最多 64 个未过期结果，全局最多 1024 个。超过上限明确失败并引导更窄查询，不生成断裂 JSON。结果清理删除内容而保留必要审计元数据。

工作预算仍以当前 65,536 词元为起点。评估 131,072 与 262,144 时必须有模型容量依据，并为输出和推理预留空间；不能从模型名称推断容量。修复现有按字符数除四对中文偏低的估算，统计真实工具模式、历史及运行上下文，超预算拒绝或压缩，不用付费长输入填窗。没有可靠容量证据时保留当前默认值，并把配置 128K 的条件和确定性边界验收记录清楚。

## 6. 反向验收标准

| 标识 | 必须证明的结果 | 关键失效与观察点 |
|---|---|---|
| API-01 | 新标准接口自动发现，业务事实只维护一份 | 新增映射后目录出现，未开放不可见；变更契约后旧策略失效 |
| API-02 | 本人权限上限持续生效 | 无权限发现/详情/执行、伪造名称、禁用用户、撤权、部门范围缩小；观察无数据泄漏和无业务写入 |
| API-03 | 原业务入口完整复用 | 与普通请求对照权限、参数错误、重复业务规则、事务效果、部门范围及操作日志 |
| API-04 | 写入受确认、停止和重复请求约束 | 未确认零写入；重复确认单次副作用；停止后零新增动作；超时未知不重试 |
| API-05 | 结果、历史和模型续跑不成为绕行通道 | 跨账号句柄、过期、权限撤销、范围变化后读取和模型请求均拒绝敏感内容 |
| API-06 | 渐进披露真实有效 | 截获实际模型请求证明初始不含全量模式、加载后仅出现选定模式；真实模型完成代表业务任务 |
| API-07 | 上下文和测试成本有界 | 中文与大模式边界、超预算、结果分页；累计代理请求账本涵盖失败、回退与压缩 |
| API-08 | 普通业务与既有 AI 功能保留 | 配对版本下运行原契约、构建、真实页面工具、确认、停止、历史、设置与审计回归 |

方案自审结论：上述机制承接 29 号文档接口阶段和共同约束。特别修正了只重用登录缓存、只过滤搜索列表、反射调用控制器、信任浏览器执行结果及历史绕过撤权五条可能失效的路径。实现后仍须用反例和真实全栈验证，方案通过不等于阶段验收通过。
