# 受控数据库能力诉求与方案

> 版本：2026-09-21 / R1；状态：已实现并通过本阶段验收，具体版本及边界见 36。总约束见 29，计划见 35。

## 1. 目标与完成标准

让用户在本人原业务授权内发现、筛选、关联和统计数据，例如“按部门统计我可见的用户数量”“查找已停用岗位”。发现只提供摘要，选定后加载字段、类型和允许操作，结果分页读取。禁止借共享连接账号扩大权限；业务写入仍走原接口及确认流程。

| 标识 | 必须成立的结果 | 关键反例与观察点 |
|---|---|---|
| DB-01 | 库、表、字段及操作有分组治理，默认关闭，模型只发现授权交集 | 无映射表、关闭库/表、关闭字段或统计操作不可被伪造调用绕过 |
| DB-02 | 逐次复用本人原权限和数据范围，聚合也只能覆盖授权行 | 不同部门/本人/自定义/全部范围，对照原业务查询行集合与独立统计；旧令牌撤权立即生效 |
| DB-03 | 业务事实来源唯一，敏感或无法证明授权的结构不开放 | 元数据来自真实库和原查询；密码等原查询未披露字段不可选择、筛选、排序或聚合 |
| DB-04 | 只有受限查询，资源、返回量和停止由代码约束 | 注入、多语句、写操作、任意函数/关联拒绝；真实慢查询、并发超限、停止和大结果触及强制边界 |
| DB-05 | 句柄、历史及派生内容持续受原授权限制 | 跨用户/运行、权限或字段策略收紧、归属转移、到期后均不能继续披露或发给模型 |
| DB-06 | 渐进披露能完成实际分析任务，保留接口和页面能力 | 实际模型输入与统计结果；必要全栈回归、生产构建、新装和升级 |

## 2. 决策来源与边界

沿用 D-002 的原接口写入、D-003 的权限交集和既有运行/审计/上下文机制。29 号要求受控查询、关联分析、分层治理及资源限制；以下具体范围与机制是本轮自主判断。

当前仓库缺少独立的“数据库用户授权表”，不能从共享 MySQL 账号或表名猜测业务权限。首批建立三个经过核查的业务查询绑定：`SysUserMapper.selectUserList`、`SysDeptMapper.selectDeptList`、`SysPostMapper.selectPostList`，分别关联真实列表接口及服务方法。用户查询已包含部门名称和负责人关联，可做按部门分组统计；本阶段不接受模型自定义关联、原始 SQL、脚本或任意数据库连接。

绑定只指出原查询与原授权入口，不复制字段清单、数据范围算法或查询语句。字段由原查询零行结果的数据库元数据派生，库表目录来自当前连接的真实元数据。其他表显示未建立授权映射，不能直接开放。新增业务授权模型必须先证明绑定正确，不能套用当前三张表的证明。

## 3. 原业务授权和结构治理

执行前刷新当前用户，核对原列表接口的真实权限；AI 数据库开放策略独立于接口开放开关，两者都不能越过原权限。原 `DataScopeAspect` 抽出仅接受服务端实体和当前用户的可复用入口，原切面仍调用同一算法。用户、部门读取原服务方法的 `@DataScope`；岗位沿用原列表在拥有业务权限后的全局可读语义。应有范围注解缺失、未知范围值或不可靠的查询结构直接关闭。

MyBatis 使用全新空查询对象生成原查询，只注入服务端计算的 `dataScope`；不接受模型的 `params`、身份、部门范围或 SQL。外层结构化筛选、投影和统计建立在这份已授权查询之上，所以计数和分组无法越过原行集合。原字段投影与数据库列来源必须一致；无法识别来源的字段关闭。

治理页按“当前数据库 → 表 → 字段”组织。库和表默认关闭；表策略保存明确的字段集合和 `QUERY` / `AGGREGATE` 操作集合。一个视图依赖的全部业务源表都须开放，查询所使用的字段须通过对应表的字段策略；关闭部门表会关闭依赖该表的用户关联视图。授权内部使用的关联键和范围过滤属于原查询逻辑，不因此向模型额外披露。

治理表只保存开放配置及真实结构指纹。原查询、范围注解、原接口契约或字段结构变化时，旧配置失效，须重新核查开放。用户本人授权摘要、数据库及相关表策略版本共同绑定结果。复用 P8 的事务归属版本、完整性检查和保护修复失效机制，不再只检查读取者本人角色是否变化。

## 4. 查询语言、执行与限额

只接受明确字段名和有限操作：字段投影、参数化比较/包含/集合/空值筛选、排序、分组，以及计数、求和、平均、最小值、最大值。字段必须在当前可用枚举内；数值统计只接受数值字段。禁止任意表达式、函数名、子查询、用户指定表或 SQL 片段。所有值绑定为预编译参数，标识符只从已验证元数据选择。

自主选择的初始边界：每次最多 100 行、12 个投影字段、10 个筛选、4 个分组字段、6 个统计、3 个排序；偏移最多 10,000，集合最多 20 项，普通字符串值最多 256 字。完整结果最多 128 KiB；继续复用接口阶段每次披露 8 KiB、用户 64 / 全局 1024 结果和 30 分钟保留期。

当前产品使用 MySQL 8。通过任务专属查询执行器从原主数据源有界借用连接，最多占用 8 个，全局 8、每用户 2 个并发，超限直接拒绝；不改变普通业务连接池默认配置。查询使用数据库真实 `READ ONLY` 事务；主 SELECT 带 `MAX_EXECUTION_TIME(1500)`，驱动查询超时 3 秒、网络读取 4 秒、借用连接最多 1 秒。连接归还前回滚并恢复本次修改的连接设置。停止、替代或运行失效时取消实际语句，返回后再次核对运行和授权，丢弃迟到结果。

2026-09-21 经 Context7 核对 [MySQL 查询时间提示](https://dev.mysql.com/doc/refman/8.0/en/optimizer-hints.html)和[只读事务](https://dev.mysql.com/doc/refman/8.0/en/innodb-performance-ro-txn.html)：时间提示限制只读 SELECT；只读事务禁止普通表写入，但仍有临时表例外。因此只读事务和时间提示是纵深约束，不能代替结构化查询白名单。验收必须观察数据库真实拒绝和执行结束，不能只检查生成语句包含关键字。

## 5. 披露、运行与结果

增加数据搜索和详情加载两个常驻工具；详情后动态提供该视图的具体查询工具，字段与操作根据当次授权派生。接口与数据共用每运行最多 8 个已加载工具；结果继续使用同一分页读取入口，增加对 `data_` 来源的授权分派。

继续复用 `AiPendingToolCall`、`AiServerCallMapper`、原子认领、运行生命周期、结果配额和来源历史保护。仅增加接口/数据两类真实来源的授权分派，不建设通用执行平台。数据调用全部只读，无额外写入通道；操作、结果状态与业务来源进入既有审计。第三阶段生成文件时继续传递这份来源授权，当前不提前开放文件下载。

## 6. 方案自审

可检验的授权来源是原列表接口、原服务范围注解和原映射查询，而非数据库账号。结构化参数被放在已授权行集合外层，字段在所有用途上统一校验，关闭表及字段策略会使旧来源摘要失效。关联仅限原查询已含的业务关系，满足当前分析场景且不引入任意关联授权猜测。

关键风险仍需实施验证：数据库驱动是否提供可靠的物理列来源；抽取后的数据范围算法是否保持原语义；超时/取消是否真的终止 SQL；结构变化是否让旧开放失效；共享结果读取是否完整分派来源。任一项不成立，修正本方案后再推进验收，不以编译通过关闭 DB-01～06。
