## 2. P1 完成目标与边界

必须完成：

- B4 / C3：全部现有 Page Capability 统一进入 Page / Action Contract + Runtime Bindings，消除长期新旧双形态。
- C2：只拆真实高频职责，不做一次性全面前端重构。
- A1：双 ESC 与 Composer 发送快捷键收敛到薄的 AI 键盘策略入口，并保持 overlay / focus guard。
- A2：Runtime Settings UI 改为推荐优先、自定义按需展开、可恢复推荐；保留现有后端数据模型/API。
- A4：用户侧“恢复上次会话”统一为“继续上次会话”，自动恢复改为自动继续；保留历史、自动继续和 Undo Restore 行为与内部兼容命名。

明确不实现：B7 TokenEstimator、B8 RunExecutionManager、多实例、Streaming、Server Tools、MCP / Skill 产品能力、Multi-Agent、RAG、Harness、动态 Tool Policy DSL、Flyway/Liquibase、第四阶段自治能力；不重做 P0 的 Capability Protocol、Tool Policy、Agent Loop、Run Lifecycle 或 SQL Migration。

### 3.3 Contract 组织原则

- Contract 集中进入 `src/ai/pages/`，按真实领域分组，不为 23 个页面机械创建 23 套框架。
- 保留 `systemUserPageCapability.js` 样板，新建 System/User、Monitor、Tool 契约模块；只在确有复杂度时保留独立 creator。
- Contract 只保存稳定声明：pageId/pageName/route/toolPrefix、query/form 字段、permission、action suffix/schema/label/description。
- Runtime Bindings 只保存运行态：真实 handler、响应式 options / validation rules、rows/total/selection/context getter。
- 业务字段规则、字典 options、API、副作用 core 和权限事实继续复用真实页面已有来源，不复制 AI-only 业务真相。
- Tool name 由现有 `toolPrefix + suffix` 原样保持。
- 不增加第二套 Adapter、Registry 或运行时写路径。

## 4. 动态路由与 stale runtime

当前 5 个明确 legacy 动态路由：

- `/system/user-auth/role/:userId(\\d+)`
- `/system/role-auth/user/:roleId(\\d+)`
- `/system/dict-data/index/:dictId(\\d+)`
- `/monitor/job-log/index/:jobId(\\d+)`
- `/tool/gen-edit/index/:tableId(\\d+)`

另有 `/user/profile/:activeTab?`；当前 capability canonical route 继续为 `/user/profile`，tab 只是页面内部状态，不提升为新的 Page Contract identity。

处理原则：

1. Contract `route` 保存稳定 canonical pattern；页面注册时对动态页通过 `useAiPageTools(contract, ..., { route: route.path })` 写入实际 runtime route。
2. pageId 对同一语义页面稳定；参数变化生成新的 page instance/version，旧 runtime 继续由 P0 full semantic identity 判 stale。
3. 不放宽 `sameSemanticPageRuntime`，不做 fuzzy route matching，不让 Tool Result 用目标页身份覆盖执行源身份。
4. Action 导航继续使用 P0 source runtime preservation；普通 Tool 执行期间的外部导航仍判 stale。
5. Contract/catalog test 覆盖 canonical pattern 与 actual runtime route 关系。

如现有 Contract route 无法安全表达 canonical + actual runtime，只允许在当前 Contract/Registry 边界内做最小扩展；若必须改变 Capability Protocol v1 长期语义，则触发暂停条件。

## 7. Wave 3：C2 + A1 / A2 / A4

### 7.1 C2 / A1：键盘策略

当前 `AiAssistant/index.vue` 同时持有 Composer Enter/Ctrl+Enter、双 ESC 700ms arm/stop、model picker/Element Plus overlay guard、AI focus 判断和 global keydown 生命周期。

实施：

- 提取薄的 keyboard composable，只负责“事件是否应发送/中断”的策略和 ESC arm timer 生命周期。
- `AiAssistant` 继续拥有 `sendMessage`、`stopCurrentRun`、model picker ref、panel ref 等业务/UI ownership，以 callback 注入。
- 保留 focus/overlay guard、700ms、Esc 关闭 overlay 不计 stop gesture、IME/Shift+Enter/Ctrl+Enter 语义。
- 不建设 global hotkey framework/DSL。

验证：策略单测 + Browser 双 ESC/overlay/focus guard + Enter/Ctrl+Enter/Shift+Enter。

### 7.2 C2 / A4：历史 / Continue / Undo Restore

当前 `AiAssistant/index.vue` 同时包含 history loading/grouping、restore snapshot、10 秒 Undo Restore、last conversation、rename/archive。

实施：

- 提取历史/继续会话协调 composable，封装 history query/loading/grouping、continue last/history、Undo Restore snapshot/timer、rename/archive。
- Pinia store 仍是 Conversation/Message/Run 状态权威，不复制 store。
- API 和内部 `restoreConversation` / `autoRestoreLastConversation` 等兼容命名不强制迁移。
- 用户文案：
  - “恢复上次会话” → “继续上次会话”；
  - “登录后自动恢复上次会话” → “登录后自动继续上次会话”；
  - 相应空态/错误提示使用“继续”语义。
- Undo Restore 的“撤销恢复”可保留动作语义。
- 保留历史入口、自动继续、短时撤销。

验证：Browser 手动继续、自动继续、Undo Restore、历史列表/重命名/归档回归。

### 7.3 A2：Runtime Settings 推荐优先

在现有 `AiModelRuntimeSettingsDialog` 和现有 API/model 字段内完成：

- 主状态提供“自动（推荐）”与“自定义”。
- “工作上下文窗口”改为“Agent 工作上下文预算”。
- 推荐态为后端 canonical defaults：64K / auto compaction / 75%。
- 只有自定义态展开预算、自动压缩、阈值；reasoning 继续单独显式展示。
- 提供“恢复推荐设置”，写回推荐值，不新增 profile。
- 推荐常量收敛到薄 helper/constant，避免 QuickSettings/Dialog 多处硬编码。
- 不新增数据库字段，不改 API contract，不做 Model Profile 平台。

验证：推荐、自定义、保存、恢复推荐、刷新后模型数据一致、reasoning 不退化。
