## 4. 实施中发现并修复的问题

### MyBatis 字段映射

注解 Mapper 未自动完成数据库 snake_case 到 Java camelCase 映射，造成 Provider、模型、会话等字段读取为空。

修复：五个 AI Mapper 的查询字段全部显式使用列别名。

### JSON Bean

当前 RuoYi 运行上下文没有可直接依赖的全局 Jackson `ObjectMapper` Bean。

修复：AI 模块提供自己使用的 JSON 配置，不改变 RuoYi 原全局序列化体系。

### AjaxResult 字符串重载

`AjaxResult.success(String)` 会把字符串作为 `msg`，而不是 `data`。

修复：字符串型模型测试接口显式返回标准 `data`。

### Provider 令牌日志泄漏

RuoYi `@Log` 默认记录请求体，最初会把 Provider 保存请求中的令牌记录到操作日志。

修复：AI Provider 保存接口明确排除令牌字段，并在 E2E 中加入数据库断言防止回归。

### 浏览器工具元数据可信边界

前端传来的 description / schema 不能作为安全边界。

修复：浏览器只上报工具名称和可用性；正式 description、schema、risk、permission 由后端 allowlist 决定。

### Pending Tool Call

增加过期检查与恢复时权限二次校验，避免旧 Tool Call 或权限已撤销的调用继续执行。

### Diff 清理

早期实现产生过整文件换行/格式噪音。

修复后：

- 根 `pom.xml` 只保留必要新增。
- `ruoyi-admin/pom.xml` 只保留必要依赖。
- `src/layout/index.vue` 仅增加 AI Assistant 挂载。
- 用户管理页恢复 master 原结构后叠加 AI Tool，原有详情、导入、重置密码、角色分配等功能保持不变。

## 5. 第一阶段边界

第一阶段已经形成完整可运行闭环，但有意不做大而全：

- 对话采用同步 HTTP Turn；暂未做 token-by-token SSE 输出。
- Page Tool 当前只完成用户管理试点。
- Local Harness 尚未实现。
- Codex Harness 尚未实现。
- 不支持任意 DOM / 坐标 / Playwright 作为产品 Agent 操作方式。
- 暂未实现显式多 Tab `tabId` / session 绑定。
- 暂未开放删除、重置密码等危险 Tool。
- Tool Calling 能力状态用于帮助管理员选择模型；普通聊天与页面 Tool 能力仍是两个不同能力维度。

## 6. 第一阶段结论

第一阶段完成定义已经满足：

管理员可以在系统页面配置 OpenAI-compatible 服务地址和令牌，同步并选择模型；用户可以在业务页面打开同一个 AI Assistant 进行普通对话，并通过自然语言驱动当前页面注册的结构化工具。页面工具不依赖 DOM 自动化，WRITE 操作需要用户确认，最终业务写入仍复用 RuoYi 原权限、数据范围和业务 API。

该闭环已经通过真实 MySQL、Redis、Spring Boot、Vue3/Vite、HTTP 接口以及 Chromium 浏览器自动验收。
