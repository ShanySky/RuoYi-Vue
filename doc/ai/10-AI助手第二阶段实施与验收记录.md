## 2. 第二阶段完成内容

### 2.1 Runtime 与 Bug 修复

- Provider 返回的 `tool_call.id` 不再直接作为数据库/浏览器内部调用 ID。
- Runtime 为每次页面 Tool Call 生成自己的唯一 `rtc_*` ID，重复、为空或不规范的 Provider callId 不再导致数据库唯一键冲突。
- pending 状态持久化失败不再向前端直接暴露 SQL/约束异常。
- Backend CI 故意让测试 Provider 在同一个 Conversation 的第二轮重复返回同一个 tool_call.id，两轮均成功完成并进入 RESOLVED。
- 用户管理语义明确：
  - `userName` = 登录账号，现有 RuoYi 编辑流程不支持修改。
  - `nickName` = 用户昵称，可通过当前 AI 页面 Tool 修改。
- System Prompt、后端 Tool Policy、前端 Tool 描述和预览 mock 均同步该语义，不再把登录账号修改误映射成昵称修改。

### 2.2 AI 窗口

AI 助手现在支持：

1. 收起：右下角 AI 按钮。
2. 默认：右下角非模态小聊天窗口。
3. 展开：右侧 Dock 工作区。

行为：

- 小窗和 Dock 都不产生聊天遮罩。
- AI 打开时业务页面仍可正常查看和操作。
- Dock 占据右侧真实布局宽度，主业务页面和 fixed header 被压缩，而不是被覆盖。
- Dock 默认宽度约 560px，可拖动调整，并持久化宽度。
- 小窗 / Dock / 收起切换共用一套 Conversation、消息、Tool 状态、模型、reasoning 和输入状态。

### 2.3 输入快捷键

默认：

- Enter：发送。
- Shift+Enter：换行。

可切换为：

- Ctrl+Enter：发送。
- Enter：换行。
- Shift+Enter：换行。

发送方式保存到浏览器 localStorage，并已通过页面重载后的自动验收。

### 2.4 聊天内快捷设置

小窗和 Dock 均提供快捷“设置”入口，不需要离开当前业务页面。

可完成：

- Base URL。
- Token。
- 启用/禁用 Provider。
- 测试连接。
- 同步模型。
- 搜索/启用模型。
- 设置默认模型。
- 测试模型 reasoning 能力。
- 设置默认思考档位。

原完整 AI 配置页继续保留，并与快捷设置使用同一后端数据源。

### 2.5 多模型与联想搜索

- 支持同时启用多个模型。
- 配置页与聊天模型选择均支持实时部分匹配。
- 前缀匹配优先，包含匹配其次。
- 不要求完整输入模型名或按回车后才搜索。
- 空输入不会一次铺开全部模型，只展示当前、默认、最近和少量常用模型。
- 最近使用模型保存于浏览器本地。

### 2.6 默认模型与 Reasoning Effort

- 每个模型可以设置默认 reasoning effort。
- 新会话自动使用默认模型及其默认档位。
- 聊天输入区只常驻显示模型，不直接暴露思考档位。
- 支持 reasoning 的模型在模型选择器中提供二级“档位”入口。
- reasoning 能力测试会实际尝试标准档位：
  - minimal
  - low
  - medium
  - high
  - xhigh
- 只把 Provider 实际接受的档位记录到 `reasoning_efforts`，前端只展示已验证档位。
- 能力未知或未确认支持时不会主动传入 reasoning effort。

### 2.7 同一会话切换模型 / 档位

同一 Conversation 可以在后续用户消息中切换：

- modelId / modelCode。
- reasoningEffort。

新选择从下一条新的用户消息开始生效。

如果上一轮正在等待页面 Tool Result：

- Tool Result 恢复时强制使用产生该 pending Tool Call 时保存的原模型和原档位。
- UI 此刻的新选择不会污染旧 pending call。
- 下一条新的用户消息才使用新的选择。

数据库现在可以追溯每条消息/Tool Call 实际使用的：

- modelId。
- modelCode。
- reasoningEffort。

## 3. 正式 Provider 与 Mock 边界

正式产品仍以用户配置为唯一运行来源：

`Base URL + Token → /models → 模型启用/默认 → Agent 调用该 Provider`

最终源代码审计确认：

- 产品源代码中没有写死 `mock-agent-model`。
- 产品源代码中没有写死预览 mock 地址。
- 产品源代码中没有 CI/Preview Token。
- 不存在正式 Provider 失败后自动回退到 mock 的逻辑。

mock 只存在于：

- Backend CI。
- Fullstack E2E。
- 临时 Public Preview workflow。

本次没有用户提供可用于外部第三方模型服务的真实 Token，因此没有对某个具体第三方 Provider 做专属凭据验证；OpenAI-compatible 请求链、模型同步、reasoning 参数、Tool Calling 和动态 Base URL/Token 路径均已通过隔离测试 Provider 完整验证。

## 4. 日志与安全基线

第一阶段日志保护继续保持：

- sys-info：50MB/文件，30 天，1GB 总上限。
- sys-error：20MB/文件，30 天，512MB 总上限。
- sys-user：50MB/文件，30 天，1GB 总上限。
- 历史日志 gzip。
- AI 默认 INFO。
- Spring AI 默认 WARN。
- Provider Token AES/GCM 密文存储。
- Provider 保存操作日志排除 Token。
- Prompt / Response / Token 不默认全量写入普通日志。
