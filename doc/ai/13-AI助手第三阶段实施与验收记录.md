### 官方资料复核

2026-09-18 已重新核对：

- OpenAI 当前 API 提供可选 `prompt_cache_key`，GPT-5.6+ 还提供 prompt cache options/diagnostics 能力。
- Spring AI 2.0.1 `OpenAiChatOptions` 原生支持 `promptCacheKey` / `extraBody`。
- Spring AI 2.0.1 `Usage` 原生提供 `getCacheReadInputTokens()` / `getCacheWriteInputTokens()`；OpenAI 主要提供 cache read tokens。

### 实际请求结构调整

- System Prompt 从动态 route/page context 中拆出，保持长期稳定。
- Checkpoint 放在稳定系统规则之后。
- 动态 route / page instance / page context / 当前可用工具后置到最新用户消息前。
- Tool Result resume 保持严格 USER → ASSISTANT(tool) → TOOL 顺序，不为了缓存破坏协议。
- conversation 请求使用 `ruoyi:conv:<conversationId>:system:<promptVersion>` cache key；compaction 使用独立 conversation compaction key。
- Run Usage 改为跨主调用/压缩调用累计。

### Cache Usage 证据

- mock response 提供 cached token usage。
- `ai_run.input_tokens > 0`、`cache_read_tokens > 0`、`total_tokens > 0` 断言通过。

- 该证据证明 Spring AI → Provider → Usage → DB 链路成立。

## 9. R3-06 Reasoning

### 实际支持档位

- 后端通用能力探测会分别尝试 `none / minimal / low / medium / high / xhigh / max`；不支持的值不会写入模型支持列表。
- GPT-5.6 目标档位仍按方案以实际探测结果收敛到 `none / low / medium / high / xhigh / max`；`minimal` 只在其他 Provider 真正支持时作为独立档位存在。

### 中文映射

- `none → 无`
- `minimal → 最低`
- `low → 低`
- `medium → 中`
- `high → 高`
- `xhigh → 极高`
- `max → 最高`

## 12. R3-10 完整语义化页面能力

### Page Capability 协议

2026-09-18 已形成 `ruoyi-semantic-page-v1` 基础协议：

- 前端 `toolRegistry` 为当前页面注册 `pageId / pageName / route / pageInstanceId / pageVersion`，页面切换或重新注册会产生新实例。
